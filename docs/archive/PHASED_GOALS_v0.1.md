# PHASED_GOALS.md — CJ-VMT 数据集阶段目标、依赖与验收计划

> 版本：v0.1（研究规划） | 2026-11-16  
> 负责人：研究者；AI Agent 负责实现与记录，但不能代替人类审查或授权。  
> 当前状态：**P0 / 规划阶段**；下文的路径、数量和指标均为目标，不代表已完成。  
> 配套指令：`AGENTS.md`。

## A. 项目 North Star 与交付物

**研究问题**：针对中日口语/字幕翻译，当原始台词存在省略、语义歧义、指代不清、语气或语体依赖时，真实视频动作、表情、场景与语音韵律能否提供文本上下文之外的增量信息？模型何时应使用、何时应忽略这类信息？

**主方向**：日语（Ja）→ 简体中文（Zh-Hans）。第二阶段扩展中文→日语。

**最终成果**：

1. 一个按来源权利管理的原始素材库（内部使用，不预设公开再分发）。
2. 一个包含原视频标识、片段、音频、双语字幕、时间戳、多模态证据、人审状态的标准化数据集。
3. 一个筛选严格的 **Video/Audio-helpful Benchmark**，并包含一般样本与负例。
4. 一套可复现的视频切片、ASR、对齐、候选标签、审核、去重、切分、导出流水线。
5. 文本、视频、音频和全模态 Baseline 与至少一组小规模多模态 SFT/LoRA 实验。
6. Data Card、标注规范、质量报告、授权台账、实验复现说明及潜在论文材料。

**核心成功标准不是数据量，而是：**输入合法、证据可信、人工译文可靠、测试集独立、视频/音频有用性可验证。

## B. 总览与阶段依赖

```text

 ↓ Gate 0：目标、数据 schema、评测方案经确认
P1 资源发现与合法性审核

P2 视频分段、音频、字幕/时序对齐
 ↓ Gate 2：20 条样本成功通过端到端处理 + QA
P3 候选动作/表情/语音证据提取
 ↓ Gate 3：证据锚点可核查，观察与推断分离
P4 翻译、人类复核、歧义审定
 ↓ Gate 4：100–200 条人审样本 + 标注一致性审计
P5 去重、分组划分、Benchmark 与 Data Card
 ↓ Gate 5：测试集冻结、无已知交叉泄漏和答案泄漏
P6 Baseline + 小规模 LoRA/QLoRA
 ↓ Gate 6：有可复现实验与明确模态增量结论
P7 扩容、二次验证、研究交付与合规发布

```

推荐阶段门槛：先 **20 条端到端样本** → **100–200 条独立双语人审的试验样本** → **约 1,000 条候选素材的筛选池** → 证明可行后扩展 **3,000–10,000 条训练样本**。数据数字为建议规模，无法保证筛选池能产生固定比例的高价值歧义样本。严格测试集数量由实际高质量样本供给决定，而非优先凑数。

## P0 — 研究定义与设计冻结

### 目标

将研究愿景转成可操作的机器翻译任务、样本类型、模态对照和可审查 schema。防止后期出现“视频有但没用”的问题。

### 输入与前置条件

- 已确定目标：Ja→Zh-Hans（主方向），视频片段 + 原语音 + 台词 + 必要前后文 → 语境适配译文。
- 研究者明确预期的使用与发布方式：仅内部、限定研究共享、或拟公开数据集。

### 要做的事情

1. 阅读 EVA、VISA、TriFine 以及近期视频字幕翻译评测工作，整理任务差异、目标语向、视频授权限制、歧义定义、评价不足。
2. 定义什么是一个样本：一条真实口语片段及其完整场景引用；优先 5–15 秒，但允许为句意完整性延长上下文窗口。
3. 明确输入对照：文本 `T`（须保持相同文本上下文）、`T+V`、`T+A`、`T+V+A`、`T+无关V`。
4. 创建歧义分类：`ellipsis`、`pronoun_reference`、`polysemy`、`speech_act`、`emotion_prosody`、`register_politeness`、`speaker_identity`、`scene_event`。
5. 定义核心评测样本门槛：**文本存在真实不确定性；人看/听证据后可以合理选择更准确译法；证据有时间锚点；至少两个审核意见；不存在字幕叠加泄漏。**
6. 决定 canonical JSONL schema、字段枚举、`unknown` 值、人工/机器标签来源字段、授权台账格式。
7. 设计盲评 + 视频/音频复核 + 争议裁决流程；明确参考译文和解释标签如何存储。
8. 敲定数据拆分和评估原则；测试集先冻结，不允许随后按模型表现调整测试题。

### 预期文件

- `docs/research_scope.md`：任务定义、范围、不做什么及研究假设。
- `docs/literature_matrix.md`：代表论文、数据集、语向、许可和差异。
- `docs/annotation_guideline.md` v0.1：人审说明与示例。
- `schemas/sample.schema.json` 和 `schemas/source_registry.schema.json`。
- `docs/evaluation_protocol.md`：基线、模态消融、评价指标、人工标注方法。
- `docs/decision_log.md`：策略变更记录。

### Gate 0 验收

- [ ] 研究者确认 Ja→Zh-Hans 优先、Zh→Ja 延后。
- [ ] 数据 schema 能表达“文本够用”“视觉有用”“音频有用”“证据不足”。
- [ ] 至少 5 条**虚构/合成**测试样本通过 schema validator；这些样本不能计入实际数据集。
- [ ] 模态对照严格匹配文本和文本上下文；不混淆上下文增益与视频增益。
- [ ] 人类审核职责和许可边界已写清。

**对下一阶段的作用**：明确了应该寻找哪些视频、需要保存哪些法律信息和元数据，避免 P1 盲目搜集素材。

## P1 — 视频源发现、许可与候选池建设

### 目标

获得**可合法用于预期处理方式**、包含真实对话与可观察多模态线索的素材，以及完整来源记录。

### 输入

P0 的素材标准、许可台账 schema、拟使用范围（研究/模型训练/发布）。

### 要做的事情

1. 制作素材来源优先级：
   - 第一优先：自制短剧、可获取书面授权的录制素材，允许音视频处理、标注与模型训练。
   - 第二优先：确有明确许可且授权方式匹配的公开对话素材；对视频、音轨、字幕分别核验。
   - 第三优先：第三方研究数据集申请许可或受限研究访问，逐条确认二次使用、衍生和发布条款。
   - 不默认使用无授权的动漫、影视、平台视频爬取资源；**公开能看不代表能下载、训练或再发布**。
2. 创建 `source_registry.csv`：来源 URI、权利人、素材种类、授权证据 URI/文件、允许操作、禁止操作、获取日期、同意状态、删除请求处理方案、限制、审核人。
3. 优先选择包含明确人脸/身体动作和情绪/语气差异的日语真实对话片段；日译中优先。
4. 记录源视频和字幕版本；为每个 `parent_video_id` 计算 sha256/指纹；保存元信息、讲话人数量和字幕存在性。
5. 进行短片试采（有授权后）：先 5–10 个源视频，估算真实台词数量和潜在有帮助样本密度；版权情况与资源丰富度同时评分。
6. 标记是否有烧录目标语字幕（硬字幕）或叠加内容；存在直接答案泄漏时要排除或创建规范遮挡流程。
7. 建立不可公开素材访问隔离及删除/撤回响应机制。

### 预期文件

- `manifests/source_registry.csv`。
- `docs/data_sources.md`：选源理由、授权、限制与成本。
- `reports/source_feasibility.md`：候选源的语义价值、可用数量、风险与高价值线索密度。
- `configs/ingest_sources.yaml`：**只包含已经核准可处理的来源**。

### Gate 1 验收

- [ ] 候选来源有可核查的授权与使用范围；缺证据的源不进入批处理。
- [ ] 至少 5 个可用源素材或等价的自制素材方案可用于试验（建议值，可依授权实际调整）。
- [ ] 能明确回答原视频/音频/字幕是否可再分发；若不能，只规划内部或受限使用。
- [ ] 有样例证明存在可观察动作/语音线索，而非纯静态景物视频。

**对下一阶段的作用**：提供可处理的源视频、字幕和权限信息，P2 才能合法启动预处理。

## P2 — 视频分段、音频提取、字幕与时序对齐

### 目标

把来源各异的长视频转换为**内容、时间轴、字幕、音轨可关联**的标准化片段。

### 输入

P1 授权视频、字幕（SRT/ASS/VTT 或原始逐字稿）、源视频 manifest。

### 要做的事情

1. 用 `ffprobe` 提取分辨率、FPS、时长、声道/采样率、编码格式；保存元数据。
2. 用 `ffmpeg` 提取音频（建议 16 kHz mono 供 ASR，保留高质量原音频备查），为片段建立 sample_id。
3. 解析字幕及时间轴；无可信日语逐字稿时进行 ASR 生成候选，并对语音转录准确性做人工抽样审查。
4. 可选 WhisperX/对齐工具进行 Forced Alignment；**翻译后的目标语字幕不能直接当成原语音强制对齐文本**，需先有原语种逐字稿。
5. 将日语说话事件与字幕片段关联；说话人分离结果不确定时保留 `unknown`。
6. 结合字幕边界、说话停顿、场景切换生成 5–15 秒左右的候选片段；对语义不完整片段延长语境窗口或保持跨段链接。
7. 记录时间轴映射：原始 `parent_video` 的绝对时间 + clip 局部时间，避免证据时间戳错位。
8. 自动质检：片段可解码、音视频非空、源文本与台词时间交集合理、越界、重复、过短/过长、硬字幕提示。
9. 抽检 20 条端到端样本，覆盖多人对话、短句、静音、快切、台词不清等边界情况。

### 预期文件

- `manifests/clip_manifest.jsonl`。
- `data/interim/asr_candidates.jsonl`、`data/interim/alignment_candidates.jsonl`。
- `data/processed/clips/`、`data/processed/audio/`。
- `reports/preprocessing_qa.md`（成功率、失败原因及样例）。
- `scripts/preprocessing/`：解码、分段、对齐、QA。

### Gate 2 验收

- [ ] 20 条经许可的样本可完整执行 ingest→clip→audio→transcript→timestamp。
- [ ] 每个样本可回溯至 parent_video、授权条目和起止时间。
- [ ] 自动检测时间戳越界、转写缺失、视频损坏；人工抽检纠正误对齐。
- [ ] 目标语言硬字幕泄漏问题有排除/遮挡/审查策略。

**对下一阶段的作用**：为视觉和语音标签提供精确对应片段，避免动作证据和台词不属于同一时间段。

## P3 — 多模态候选证据生成与时间锚点

### 目标

用自动工具高效提出可审查的视觉、动作和语音线索候选，但不将其直接写成最终真值。

### 输入

通过 P2 处理的标准 clip、音轨、原文与统一时间轴。

### 要做的事情

1. 视觉：按固定采样率（例如先 1–2 fps）提取关键帧，同时考虑短暂手势可在必要时增帧；必须记录 frame timestamp。
2. 动作/姿势：记录摇头、点头、指向、挥手、后退、拥抱等**可观察动作**及起止时刻。
3. 表情：记录嘴角上扬、皱眉、目光转向等可观察现象；对于“嘲讽”“厌恶”这样的解释需独立标记为推断/待核验。
4. 场景：人物关系、位置、手持物、与台词相关事件；避免生成与翻译无关的冗长视频描述。
5. 音频：保存 ASR 置信度、语速/停顿、音量/重音变化等可检验特征；情绪判断只写成候选。
6. 引入双语/多模态候选判别器筛选“可能需要模态消歧”的片段；与真实人工标签隔离。
7. 建立 evidence item：`modality`、`timestamp_ms`、`observable_cue`、`hypothesis`、`annotation_source`、`model_version`、`confidence`、`review_status`。
8. 用抽样人工审查看候选证据的可见性和对应台词是否正确；记录误检类别、不同采样率下漏掉的短手势。

### 预期文件

- `data/interim/visual_candidates.jsonl`。
- `data/interim/audio_candidates.jsonl`。
- `data/interim/helpfulness_candidates.jsonl`。
- `reports/evidence_qa.md`。
- 抽帧/候选证据抽检辅助界面或可复核的 html 报告。

### Gate 3 验收

- [ ] 候选视觉/音频标签都有时间戳和媒体引用。
- [ ] 可观察事实与推断解释是独立字段。
- [ ] 至少完成一轮小样本人工抽查，并记录常见误检；无依据标签不会自动进入 gold。
- [ ] 模态缺失/不可判定有明确枚举值。

**对下一阶段的作用**：让人类译者看到可追溯的候选信息，提高核查效率，但不被自动标签强迫接受某个译文。

## P4 — 双语翻译、盲评、证据审核与歧义裁决

### 目标

建立**真正可信的人工参考译文**，并确认视觉、音频到底改变了什么。

### 输入

P2 的台词/片段，P3 的候选证据，P0 的标注指南。

### 要做的事情

1. 原语逐字稿复核：检查 ASR 对短句、语气词、说话人、口音、角色名和含混词的误识别。
2. 可以用 PLaMo 3 Translate 8B 或其他 MT 模型给出**文本翻译候选**，但不能直接称其为 gold reference。
3. **盲态 A**：译者只见原文 + 固定文本上下文，记录候选译法、未解决歧义、文本条件置信度。
4. **多模态态 B**：译者/审核者查看音视频，独立产出或修订译文，明确改变译文的视觉/音频事实和起止时间点。
5. **模态归因态 C**：逐项判断只看视频能否确定、只听语音能否确定、两者是否互补、其实只要文本上下文就足够。
6. **双人独立审核**：核心测试样本至少 2 位能阅读日文、理解中文的人独立评价；不一致则第三人裁决或标为 `uncertain`。记录 Cohen's κ / Krippendorff's α（适用于分类标签）和分歧矩阵。
7. 加入视频中无关信息的审查：如果视频只出现说话者却无法支持目标含义，就不能标 `visual_helpful=yes`。
8. 纠正自动译文的事实性、礼貌级别、性别假定、指代、语气和中文自然度；金标准允许多个合理译文或明确条件限制。
9. 记录 `reference`、`acceptable_alternatives`、`text_only_candidate`、`change_reason`、`visual_evidence`、`audio_evidence`、`adjudication`。
10. 构建少量严格控制的 counterfactual pairs：原文及文本上下文一致，但真实视听场景不同，人工确认正确翻译不同；**禁止凭空给任意调换的视频编造“正确参考译文”**。

### 预期文件

- `docs/annotation_guideline.md` v1.0（含争议案例）。
- `data/annotations/human_reviews.jsonl`。
- `data/annotations/adjudicated_gold.jsonl`。
- `reports/annotation_agreement.md`、`reports/ambiguity_catalog.md`。
- `scripts/annotation/`：标注导入/冲突统计/差异复核。

### Gate 4 验收

- [ ] 获得约 100–200 条合格人审样本（建议目标，若产量不足先定位原因），覆盖不同标签。
- [ ] 每条 gold 有真实源视频、审核过的逐字稿、合法来源、参考译文和必要证据。
- [ ] 核心歧义样本具有独立复核记录，争议样本有明确裁决或剔除。
- [ ] 产出可计算的标注一致性与分歧报告；低一致性的类别有具体改进计划。
- [ ] `visual_helpful` 与 `audio_helpful` 的正例不是仅由自动模型自评产生。

**对下一阶段的作用**：提供可信 gold 集，P5 才能分层筛选和冻结有学术价值的测试集。

## P5 — 数据清洗、分层、切分与 Benchmark 固化

### 目标

创建既能训练又能严谨验证“模态帮助”的数据集，而非只追求大规模收集。

### 输入

P4 审核标签，P1 授权台账，P2/P3 媒体与证据索引。

### 要做的事情

1. 过滤：无许可、解码损坏、严重噪音、对齐错误、原文本不明、译文未复核、有目标语答案覆盖、无证据的“视觉有帮助”标签。
2. 去重：片段 SHA256、视频/音频近重复、相同镜头、重复字幕；同一影视节目/频道/拍摄源归为 group，避免跨集合泄漏。
3. 标签分层：`visual_helpful`、`audio_helpful`、`both`、`text_sufficient`、`uncertain`；按歧义种类、说话人数、时长、场景和素材域统计。
4. 先划分并冻结 `test`，再划分 `dev` 和 `train`。按 `parent_video_id/scene_id` 或更严格作品层级划分，不随机打散单句后切分。
5. 在测试集选取核心困难子集；设置普通样本子集和负例子集，不以无根据硬阈值强行凑数量。
6. 对每条测试样本维护 A/V/C 信息可见条件；报告是否存在“字幕本身提供所有答案”的捷径。
7. 生成数据统计与 Data Card：语言对、来源、权利、样本量、模态覆盖、歧义分布、分割策略、限制及可能偏差。
8. 设计面向训练的 exporter：canonical JSONL → ms-swift 等模型格式；仅把训练输入允许看到的信息写入 user prompt。

### 预期文件

- `manifests/split_registry.jsonl`（版本冻结）。
- `data/annotations/gold_v1.jsonl`。
- `data/annotations/train_v1.jsonl`、`dev_v1.jsonl`、`test_v1.jsonl`（内部受控路径）。

## P6 — 基线评测与小规模微调验证

### 目标

回答三个问题：（i）文本模型是否已经能翻译好？（ii）给视频、音频有无真实增益？（iii）SFT 是否学习到有益的模态使用策略？

### 输入

冻结的 P5 数据与评测协议、经核对可用的模型与 GPU 环境。

### 要做的事情

1. Text-only：PLaMo 3 Translate 8B BF16（或另一强基线），在相同文本上下文上翻译，保存生成参数和输出。
2. Multimodal zero-shot：选择能实际读取视频的 Qwen3-VL-8B 实现 `T+V`；用实际支持音频和视频的模型实现其他输入条件。**跨骨干比较不得直接作为“模态有效”的唯一证据**。
3. 同骨干消融：在能力允许的模型上固定 Prompt、数据和生成参数，仅增加/剔除模态；必要时统一使用 ASR 台词作为 T 输入。
4. 小规模 LoRA：只使用 train，开发集调参，测试集只最终评测；初始视频可减少帧数/分辨率，GPU 选型经真实短跑验证。
5. 评价：chrF++（日中字符级较稳）、适用于相关语向且经验证的 COMET、人工忠实度/自然度、歧义消歧准确率、语气/敬语保留、Hallucination、负例稳定性。
6. 显式负例：`T+irrelevant V`、`T+shuffled V`；报告错误地跟随无关视频的比例。
7. 统计比较：按歧义类别和模态 helpfulness 分层，使用 bootstrap 置信区间或 paired significance，分析困难样本的错误案例。
8. 输出模型运行成本：延迟、显存、tokens/帧数、推理吞吐；不能靠牺牲文本准确率换取少数案例改善。

### 预期文件

- `baselines/`：纯文本、多模态基线的配置与适配器。
- `experiments/`：每次训练 YAML、日志、checkpoint 索引和预测输出。
- `reports/baseline_results.md`、`reports/ablation_results.md`、`reports/error_analysis.md`。
- `docs/model_card_draft.md`（若发布微调权重）。

### Gate 6 验收

- [ ] Text-only、T+V、T+A、T+V+A 中可实现的条件有真实运行记录；不可实现的条件诚实说明，不虚构。
- [ ] 至少一次可复现小规模训练/推理评测，记录模型版本、随机种子、显存和数据版本。
- [ ] 有人工案例、子集指标和负例分析，判断模型是否真正利用视频/语音而非外部文本提示。
- [ ] 不仅报告“整体 BLEU 提升”；解释模态帮助和误导发生在哪些具体场景。

**对下一阶段的作用**：把数据集缺陷和模型失败原因转化为下一轮采样策略，以证据驱动扩容。

## P7 — 有针对性的扩容、版本发布与论文材料

### 目标

构成正式的研究数据集和 Benchmark，支持独立复现，并根据权利许可决定公开范围。

### 输入

P6 错误分析和多模态收益、P5 冻结的评测标准、P1 更新的授权台账。

### 要做的事情

1. 有目标地扩充容易误译的类别（省略、语气/拒绝、指代、礼貌级别、短手势），而不是单纯增加随机样本。
2. 在质量控制和审查能力允许时，将训练样本扩展到建议的 3,000–10,000 条；若核心模态有帮助样本稀少，应披露真实数量和筛选率。
3. 新增素材与旧测试集严格隔离；如果必须更新测试集，以新版本发布并保留旧版本用于可比性。
4. 可选推进 Zh-Hans→Ja：单独审核敬语、语体、反向翻译自然度及标注质量；禁止将日译中参考直接逆向视为反向 gold。
5. 对不同类型/长度/素材域的样本做稳健性分析与人工误差剖析。
6. 编制统计表、模型对照表、模态消融表、示例可视化、数据流程图、论文初稿和可重复实验说明。
7. 根据视频、音轨、字幕及派生权利分别决定：公开全部、公开经许可子集、只公开清理后的标注/索引、或仅提供受限研究访问。

## E. 研究风险与处理优先级

| 风险 | 严重性 | 应对 |
|---|---|---|
| 影视/动漫视频、字幕版权不明 | 极高 | 自制/授权优先；分资产权利台账；内部与公开版本隔离 |
| 候选视频多数无需视觉即可翻译 | 极高 | EVA 式 helpfulness 审核；保留负例；优先收集真实歧义场景 |
| ASR 错误导致翻译任务不纯 | 高 | 人审日语逐字稿；把 ASR 错误单独标记 |
| 译文受标签泄漏或烧录中文字幕影响 | 极高 | 自动检查 + 人审；训练与测试隔离目标字幕 |
| 将文字上下文收益错记为视觉收益 | 极高 | 同一文本上下文、同骨干消融及反事实测试 |
| 自动生成标签冒充金标准 | 高 | `annotation_source` 和审核状态强制分离；gold 人审 |
| 表情/动作误解，语气解释过度 | 高 | 观察与推断分开，音视频/上下文交叉核查 |
| 同一原视频切分到 train/test | 高 | 来源/作品/场景 group split + 近重复检查 |
| 多模态训练显存、吞吐成本过高 | 中 | 先短视频/少帧数 LoRA，再按效果扩展 |
| 模态有益子集比例极低 | 中高 | 分层采样与失败案例报告，不追求虚假大规模 |

## F. 合作与人审要求

1. **AI 可以辅助**：检索文献、提出候选、转录、初译、抽取可观察线索、编写工具、生成审查页面、计算 QA 指标。
2. **AI 不能代替**：视频版权许可、参与者同意、独立人类金标准、对语用歧义的最终裁决、研究结论的真实性审计。
3. 在标注预算有限时，优先将人工成本用于**核心 Benchmark**，而非均匀审核所有大规模训练候选。
4. 人工标注者先接受说明和示例训练；对被模型自动标注影响的流程要记录是否存在锚定偏差。
5. 所有发布版本都应说明样本来自哪些场景和类型，避免宣称可代表全部日常中日会话。
