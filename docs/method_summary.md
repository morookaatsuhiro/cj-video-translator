# 方法总结：中日多模态视频翻译系统（CJ-VMT 结课版）

> 2026-11-24 | 用于课程汇报和项目说明。结果部分留空，等系统真正跑完再填，不能先写数字。

---

## 1. 要解决的问题

中日口语翻译里，有一部分必须表达的信息，文字里根本没有，只能从声音和画面里得到：

| 现象 | 例子 | 只看文字的问题 | 信息在哪里 |
|---|---|---|---|
| 是不是提问 | 中文“你明天也去”（语音识别转写出来没有问号） | 日语要决定写不写「か」 | 句末语调 |
| 对谁说话 | 同一句“你明天也去吗？” | 对老师要用「いらっしゃいますか」，对朋友用「行く？」 | 画面：说话对象 |
| 接受还是拒绝 | 日语「いいよ。」 | 中文“好啊”和“不用了”意思相反 | 点头还是摆手、语气 |
| 是谁 | 日语省略主语「来るって言ってた」 | 中文要选“他”或“她” | 画面里是谁 |
| 指什么 | 日语「それ、取って。」 | 中文可能要说出具体东西 | 手指的方向、桌上的东西 |

研究问题：**给全模态模型加上声音和画面，中日翻译里这类信息能不能译对？能不能把这种能力系统地测出来、教给模型？**

## 3. 方法

### 3.1 核心思路：控制变量的对照

用**同一个**全模态模型（Qwen2.5-Omni），只改变它能拿到的信息，看译文怎么变：

| 条件 | 给模型什么 | 回答什么问题 |
|---|---|---|
| A `T_neutral` | 文字（句末问号统一改成句号） | 只靠文字能译到什么程度（下限） |
| B `T_asr` | 语音识别出的文字（保留它自己加的标点） | 语音识别留住了多少语调信息 |
| C `T+A` | A + 声音 | 声音有没有用 |
| D `T+V` | A + 无声画面 | 画面有没有用 |
| E `T+V+A` | A + 画面 + 声音（按模型原生的方式，把声音和画面按时间交错输入） | 两者一起是否更好 |
| `T+A_shuf`、`T+V_shuf` | A + 别的视频的声音或画面 | 模型是真的在用证据，还是随便变 |

三条设计原则：

1. **同一个模型、同一组参数**，各条件只差一句“请参考随附的语音/画面”。这样差异只能来自输入的信息，不是模型不同。
2. **文本中性化**：语音识别加的问号已经带有语调信息。如果留着它，“声音有用”就被文字吃掉了，所以 A 组把句末问号统一换成句号。
3. **反事实对照**：把声音或画面换成别的视频的，如果译文照样“变好”，说明模型不是在用证据。

### 3.2 评测：按现象判对，不只看总分

BLEU、COMET 这类总分测不出“问句有没有译成问句”“敬语用没用对”。所以按现象自动判对：

- **问句判对率**：原句是问句（人工转写以“？”结尾）的 129 句里，日语译文是不是问句（句末是「か」「かい」「かな」「かしら」或问号）。同时统计**误判为问句的比例**，防止模型什么都译成问句来刷分。
- **问句分层**：去掉问号以后，带“吗”“什么”“是不是”“对吧”这类标记的问句只看文字也能认出来。真正检验声音作用的是没有任何疑问标记、只靠语调的那一类（Q5），所以按 Q1–Q5 分层报告。
- **文体一致率**：译文的です／ます体或常体是否和人工参考一致。全部译成常体就有约 71.5% 的一致率，所以要和这条基线比，并报告 κ。
- **整体质量**：chrF（按字符算）和 COMET。
- **统计**：同一批句子在两个条件下的对错用 McNemar 精确检验，多组比较用 Holm 校正；比例给 95% 置信区间。

### 3.3 数据集构建的方法（交差版不做，结课后实施）

完整方法（v0.3）是一条自动流水线：

```text
授权视频 → 抽音轨 → 语音识别 → 切句 → 片段（无声画面 + 只含本句的音频）
→ 全模态模型看视频翻译（训练答案）+ 只看文字翻译（对照）
→ 两者不同的句子 → 线索核验、反事实测试、评审团 → 分桶（core / general / control）
→ 按来源切分、冻结测试集 → 导出训练格式 → LoRA 微调对照
```

交差版不建数据集，也不做试点挖掘。结课后的第一步是在 WMT 测试集上做“自动挖掘”试点：WMT 带有人工参考，可以直接判断“加了声音或画面之后，是不是从错变对”。规则存在 `docs/roadmap/pilot_spec_mvp.md`。

| 标签 | 条件 |
|---|---|
| `helped_by_audio` | A 错，C 对，换成别的声音后又错 |
| `helped_by_video` | A 错，D 对，换成别的画面后又错 |
| `helped_by_both` | A 错，E 对，但 C 和 D 单独都错 |
| `misled` | A 对，加了声音或画面反而错 |
| `unchanged` | 各条件结果一样 |

挖出来的样本按完整数据集的格式导出。它们只用来演示方法，**不能当训练数据**，因为来源是测试集。

## 4. 系统架构

```text
                 ┌──────────── 翻译系统 ────────────┐
 视频 → 媒体处理 → 语音识别 → 切句 → 片段 → 四条件翻译 → 对比与判对 → 字幕 / 对比页面 / 网页演示
                                            ↑
                        模型后端：本地 Qwen2.5-Omni ｜ OpenAI 兼容接口（可选）｜ Mock（测试用）

 WMT26 / WMT25 → 数据准备（核对统计数字）→ 各条件整段翻译 → 自动判对 → 统计检验 → 实验报告
                                                         └→ 数据集试点：自动挖掘 → 候选样本 + 浏览页
```

| 模块 | 做什么 |
|---|---|
| 媒体处理 | 读取视频信息；抽 16 kHz 单声道音轨；生成无声视频 |
| 语音识别 | faster-whisper，带词级时间戳和静音检测 |
| 切句 | 按句末标点和停顿切成一句一句，每句有起止时间 |
| 片段 | 每句的画面取前 3 秒到后 1 秒；音频只保留这一句，其余静音（防止听到别人的话） |
| 四条件翻译 | 同一模型、同一参数，只换输入；结果缓存，可复现 |
| 对比与判对 | 问句、文体、简体字混入等规则检查；标出各条件之间的差异 |
| 实验 | WMT26 中→日为主，WMT25 日→中为辅 |
| 试点 | 按 §3.3 的规则挖掘样本，导出 |
| 演示 | 网页（可离线回放）+ 静态 HTML 报告 |
| 实时模式 | 句级实时：停顿检测切句 → 识别 → 先出只看文字的译文 → 再出多模态译文并标出差异；支持模拟直播和摄像头直播（`docs/realtime_design.md`） |
| 语气保留 | 模型先说出语气（感知第 4 题），翻译时用目标语言的语气词、句末助词和标点表达；可选用 CosyVoice 按语气合成译文语音（`docs/tone_preservation.md`） |

## 7. 局限

1. **只用了一个模型。** 结论可能只对 Qwen2.5-Omni 成立。
2. **样本少。** 问句只有 129 句，按 80% 功效只能检出约 8–13 个百分点以上的差别；只靠语调的子集更小，只能检出约 14–24 个百分点以上的差别（`docs/mvp_analysis.md` §2.6）。
3. **判对规则只看形式。** 例如句末有没有「か」，口语里的问句和敬语可能判错。
4. **数据集只是试点。** 挖掘来源是测试集，标签是自动的，没有人工核对，不能用来训练。
5. **WMT 数据只能研究用。** 报告和幻灯片里不放它的视频截图，画面示例只用自录视频。

## 9. 创新点（摘要）

详细的对比、支撑证据和表述注意事项见 `docs/innovation.md`。

1. **研究对象新**：据我们检索，现有视频辅助翻译的数据和评测集中在英日、英中方向。本项目在中日方向、用真实视频，检验声音和画面能否补上“是不是提问”“礼貌程度”这类信息差。
2. **评测方法新**：按“文字能否自行恢复”分层评测。单独测量只能靠语调判断的问句（Q5），不需要新的人工标注。
3. **实验设计更严格**：同一模型只换输入。显式控制语音识别标点和音频窗口这两种泄漏，并用错配的声音和画面做反事实对照。
4. **系统即工具**：翻译系统在输出字幕的同时，自动挖出声音或画面改变了译文的句子，可以低人工地积累数据集。完整的构建方法已设计好，结课版只做了试点。
