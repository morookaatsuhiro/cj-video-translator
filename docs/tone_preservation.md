# 语气保留设计：译文也要模仿原话的语气

> 2026-11-24 | 适用于交差版的离线和实时两种模式。  
> 第 0 节起保留早期设计、参考代码与估计值。实际部署与验证见本节和进度记录。

## 当前部署的句级语调迁移

2026-11-25 的 AutoDL 网页在「生成 AI 配音」时使用三步处理。Qwen 保存语气观察与译文，CosyVoice2-0.5B 按目标语言和原声参考合成，随后 CREPE tiny 与 WORLD 在 CPU 上迁移原句的音高走势。摄像头或上传会话仍需要说话人许可。 [配音入口](../src/cjvmt/dubbing.py) · [合成进程](../src/cjvmt/cosyvoice_worker.py) · [音高迁移](../src/cjvmt/prosody.py)

1. CREPE 从实际台词时间窗提取基频与周期性，滤去静音和低置信帧。用于克隆音色的较长参考音频单独提供给 CosyVoice。
2. 对原声和译文的基频分别取短时平滑的相对音高走势，按各句有效发声的起止位置对齐。在译文明显有音高的帧上施加最多 2.5 半音的平滑调整，以保留目标语言的字声调、重音和自然停顿。
3. WORLD 用译文的频谱与非周期成分重新合成音频，音高迁移前后采样长度一致。后续仍走现有的字幕与视频时间轴对齐。可用基频太短时沿用基础配音。

这里的迁移以句级相对音高为单位。中日译句的字词数与声调结构可能不同，字词级音高、停顿和音量由目标语言合成流程决定。干净的单人录音适合验证效果。回放会显示实际应用句数，`dubbing.json` 保存模型版本、权重 SHA-256、应用的参数及逐句状态。

本机的 CREPE 权重随 `torchcrepe==0.0.24` 安装至 `.cache/cosyvoice-env/lib/python3.10/site-packages/torchcrepe/assets/tiny.pth`，同一环境使用 `resampy==0.4.3` 和已有的 `pyworld==0.3.5`。在已有 CosyVoice 环境迁移时，可用 `uv pip install --python .cache/cosyvoice-env/bin/python --no-deps torchcrepe==0.0.24 resampy==0.4.3` 安装基频模型包。配置入口是 `configs/mvp.yaml` 的 `tts.intonation`。 [TorchCREPE](https://github.com/maxrmorrison/torchcrepe) · [WORLD](https://github.com/mmorise/World)

在可控波形验收中，固定音高的目标音频起末差为 0 半音。用上扬和下落参考处理后，重新测得起末差为 +4.65 和 −4.52 半音。三种输出采样长度一致，静音参考触发回退。数值用于验证音高调整方向，实际语音的听感另行验收。 [进度与运行记录](../reports/progress.md)

## 0. 结论：要不要加一个“修改语气”的模型？

“语气”可以落在两个层面，答案不一样：

| 层面 | 指什么 | 要不要加模型 | 工作量 |
|---|---|---|---|
| **文字层** | 字幕里的译文带着原话的语气：语气词、句末助词、感叹号、口语化的说法。例如不耐烦地说「もういいよ」，译成“行了行了，别说了！”，而不是平平的“已经可以了。” | **不用加。** Qwen2.5-Omni 本来就听得到原声；只要让它先说出语气，再按语气翻译 | 约半天 |
| **语音层** | 系统把译文**念出来**，念出来的声音带着原话的情绪，最好还是原来说话人的音色 | **要加一个语音合成模型。** 推荐 CosyVoice：支持中文和日语，能用原句声音克隆音色（跨语言也可以），能按指令控制语气 | 约半天到 1 天 |

**建议**：
- 文字层一定要做：成本低，而且本身就属于这个研究的问题（歧义类型里的“语气与情绪”）。
- 老师如果要求“听得出语气”，再加语音层。
- 汇报时可以这样说：先让模型听出语气，再用目标语言自然的方式把语气表达出来；需要时，再用原说话人的音色、按同样的语气念出来。

## 1. “语气”包括什么

| 方面 | 在原话的声音里怎么体现 | 在译文文字里怎么体现 | 在译文语音里怎么体现 |
|---|---|---|---|
| 情绪（开心、生气、难过……） | 音高、音量、语速、音色 | 语气词、感叹号、用词 | 合成时的情绪 |
| 态度（不耐烦、讽刺、怀疑、撒娇……） | 拖长、平板、重音、叹气 | 特定说法（“行了行了”“你可真行啊”“真的假的？”） | 合成时的语气指令 |
| 是否提问、是否感叹 | 句尾升降 | 问号、感叹号、“吗/呢/吧”、「か」 | 句尾语调 |
| 礼貌和口语程度 | 说话方式 | 中文的“您/你”、口语词；日语的敬体或常体、终助词 | — |

## 2. 文字层：不加模型

### 2.1 做法

**做法 A：直接要求保留语气**
- 在“引导”模式的提示词里加一句：“请保留说话人的语气，用目标语言自然的方式表达。”
- 模型在 `T+V+A` 条件下听得到原声，看得到表情。

**做法 B：先说出语气，再翻译（推荐，演示效果好）**
1. “先感知后翻译”模式的第一次调用，在原来三个问题（句尾语调、动作表情、说话对象）之外加第 4 题：
   > 4. 说话人的语气：平静 / 开心 / 兴奋 / 亲切 / 生气 / 不耐烦 / 惊讶 / 怀疑 / 讽刺 / 撒娇 / 犹豫 / 难过 / 害怕 / 不确定；强度：弱 / 中 / 强。
2. 第二次调用翻译时，带上这个回答，再加一句语气要求：
   > 请保留说话人的语气（{语气}，{强度}）：用目标语言里自然的方式表达，例如语气词、句末助词、感叹号或问号、口语化的说法。不要用括号写出情绪，不要增加原文没有的意思。
3. 页面上每句显示一个语气标签，例如“😠 不耐烦（强）”，并注明“模型观察，未核实”。

**可选：声学情绪作“第二意见”**
- SenseVoice-Small 在识别语音的同时会输出情绪标签：中性、开心、生气、难过，以及“未知”。它还能检测笑声、掌声、背景音乐等声音事件。
- 把它显示在语气标签旁边。和大模型的判断不一致时，页面上标“不确定”。
- 它只有四类情绪，比较粗，只作参考。

### 2.2 中日语气表达对照（写进提示词示例和报告）

示例是虚构的，只说明表达方式：

| 语气 | 日语常见手段 | 中文常见手段 | 示例 |
|---|---|---|---|
| 亲切、随意 | よ、ね、常体 | 啊、呀、吧、啦 | いいよ → 好呀 |
| 不耐烦 | もう、～って、说得很短 | 行了行了、算了吧、感叹号 | もういいよ → 行了行了，别说了！ |
| 讽刺 | さすがだね（拖长、平板） | 可真行啊、真有你的 | すごいね → 你可真行啊 |
| 惊讶 | えっ、本当？、マジ？ | 啊？、真的假的？ | 本当？ → 真的假的？ |
| 怀疑 | 本当に？、～かな | 是吗？、不会吧 | 本当に？ → 不会吧？ |
| 犹豫、委婉拒绝 | ちょっと…、まあ… | 这个嘛……、可能吧 | ちょっと… → 这个嘛…… |
| 撒娇、亲昵 | ～もん、～てば | 嘛、～啦 | 行こうってば → 走嘛走嘛 |
| 礼貌、客气 | です／ます、敬语 | 您、请、麻烦您 | 少々お待ちください → 请您稍等一下 |

**中→日方向**（中文原话 → 日语译文）同样适用：
- 不耐烦用短句和「もう」；
- 亲切用「よ」「ね」；
- 讽刺用「さすが」；
- 礼貌程度要同时考虑说话对象（感知第 3 题）。

### 2.3 规则

- **对比模式不加语气要求**，保持各条件只差模态说明。语气要求只加在“引导”和“先感知后翻译”这两种模式里。
- 不用括号写情绪，例如“（生气地）”。字幕里只能出现说话的内容。
- 不添加原文没有的意思。语气词可以加，但不能多出新的内容。
- 感叹号和问号要和语气一致，不要满屏感叹号。

## 3. 语音层：加一个语音合成模型

### 3.1 流程

```text
译文文字 ＋ 语气标签（例：不耐烦，强） ＋ 原句的声音（作音色参考）
        ↓
语音合成（CosyVoice：音色克隆 + 语气指令）
        ↓
带语气的译文语音
├─ 离线模式：按字幕时间拼成一条配音音轨，可以导出带配音的视频
└─ 实时模式：字幕出来以后接着播放，作为第三阶段；积压时跳过
```

### 3.2 选哪个模型

| 模型 | 中文 | 日语 | 音色克隆 | 能控制语气吗 | 说明 |
|---|---|---|---|---|---|
| **CosyVoice 2 / 3（推荐）** | 能 | 能 | 能（零样本，3–10 秒参考音；支持跨语言） | 能（文字指令，例如“用不耐烦的语气说”） | 阿里通义开源，Apache-2.0（以官方仓库为准）；支持流式输出，官方称首包延迟可低至约 150 毫秒；中日两个方向用一个模型就够了 |
| GPT-SoVITS | 能 | 能 | 能（少量样本） | 主要靠参考音的语气 | 社区常用；要一段带目标语气的参考音 |
| Style-Bert-VITS2 | — | 能 | 要先训练说话人 | 能（风格向量） | 只适合日语，准备工作多 |
| VOICEVOX | — | 能 | 不能（只有固定角色声） | 有限（部分角色有几种风格） | 汇报里提过；要按角色条款署名 |
| Qwen2.5-Omni 自带的语音输出 | 能 | 能 | 不能（只有固定音色） | 不能指定 | 输出语音时必须用官方固定的系统提示词，和我们的翻译提示词冲突；还要多占显存。**不推荐** |
| SeamlessExpressive（汇报展望里提过） | 能 | **不支持** | 能 | 能保留语气 | 支持的语言是英、西、德、法、意、中，没有日语；许可受限，要申请。**用不了** |

### 3.3 CosyVoice 参考用法

接口以官方仓库 README 为准。CosyVoice 不是 pip 包，要克隆仓库、按说明装依赖；模型可以从 ModelScope 下载。

```python
import sys
sys.path.append("third_party/Matcha-TTS")             # 官方 README 要求
import torch
import torchaudio
from cosyvoice.cli.cosyvoice import CosyVoice2
from cosyvoice.utils.file_utils import load_wav

tts = CosyVoice2("pretrained_models/CosyVoice2-0.5B", load_jit=False, load_trt=False, fp16=False)

def tone_instruct(tone):
    """和 prompts_mvp.yaml 的 tts_instruct 一致：“用{tone}的语气说这句话”。"""
    if not tone or tone == "不确定":
        return "用自然的语气说这句话"
    return f"用{tone}的语气说这句话"

def speak(text, tone, ref_wav_16k, out_path):
    """text：译文；tone：语气标签；ref_wav_16k：原句的声音（门控后的 16 kHz wav，3 秒以上最好）。"""
    prompt = load_wav(ref_wav_16k, 16000)
    chunks = [j["tts_speech"] for j in tts.inference_instruct2(text, tone_instruct(tone), prompt, stream=False)]
    torchaudio.save(out_path, torch.cat(chunks, dim=1), tts.sample_rate)
```

要点：
- 原句太短（不到 3 秒）时，音色克隆效果差。可以改用同一说话人更长的一段作参考，或者换成固定的参考音色。
- 指令用中文写，日语译文也一样。
- CosyVoice 3 的接口和 CosyVoice 2 不完全一样，以所用版本的 README 为准。

### 3.4 配音和原视频对齐（离线模式）

- 每句合成的语音长度和原句不一样。比原句长时，用 `ffmpeg -filter:a atempo=<倍数>` 加速，最多到 `tts.max_speedup`（默认 1.3 倍）；还放不下就允许稍微延续到下一句开始之前。
- 按每句的开始时间把语音放到一条音轨上，导出 `dub.wav`。
- 合成带配音的视频（保留原音轨，加一条配音音轨）：

  ```bash
  ffmpeg -i input.mp4 -i dub.wav -map 0:v -map 0:a -map 1:a -c:v copy -c:a aac output_dub.mp4
  ```

### 3.5 显存和延迟（估计）

| 项目 | 估计 | 说明 |
|---|---|---|
| CosyVoice2-0.5B 显存 | 约 2–4 GB | 48 GB 卡可以和其他模型一起常驻。24 GB 卡在量化版翻译模型旁边会比较紧，可以等翻译完成后再合成 |
| 单句合成耗时 | 约 0.5–2 秒 | 流式模式能更早开始播放（官方称首包约 150 毫秒） |
| emotion2vec+（只用于评测，可选） | 约 1–2 GB | 评测时才加载 |
| 在 RTX 50 系上（例如 5090） | 官方依赖固定的旧版 PyTorch（2.3.1，cu121）用不了 | 要自己换成 CUDA 12.8 的 PyTorch 2.7 以上再调依赖，有风险；32 GB 显存时不要和翻译模型同时常驻，翻译完再合成（`docs/environment.md` §10） |

## 4. 怎么证明“语气保住了”

### 4.1 自录“语气对”

在 `docs/HUMAN_TASKS.md` H2 的录制清单里加三对。同一句话，换一种语气说：

| 对 | 台词 | A 版 | B 版 | 预期 |
|---|---|---|---|---|
| pair06 | すごいね。 | 真心称赞（笑着、语调上扬） | 讽刺（平板、拖长、翻白眼） | A：真厉害！/ B：你可真行啊。 |
| pair07 | 本当？ | 惊喜 | 怀疑（皱眉） | A：真的吗？太好了！/ B：真的假的？ |
| pair08 | もういいよ。 | 温和（没关系了） | 生气（不耐烦） | A：好啦，没事了。/ B：行了行了，别说了！ |

### 4.2 指标（演示级，样本很小）

| 指标 | 怎么算 | 说明 |
|---|---|---|
| 文字语气是否跟着变 | 每对的 A、B 两版，多模态译文是否不同、而且各自符合预期 | 由你判断（只有几对，几分钟就能看完），或者用文本大模型判断，标明“自动判断” |
| 只看文字 vs 多模态 | 同一对里，只看文字的两版译文必然相同（输入一样）；多模态的两版是否分开了 | 最直观地说明“语气要靠声音和画面” |
| 语音语气一致率（做了语音层才有） | 用 emotion2vec+ 分别识别原句和合成语音的情绪类别，看是否一致 | emotion2vec+ 有 9 类：生气、厌恶、害怕、开心、中性、其他、难过、惊讶、未知。识别本身会出错，只作参考 |

如实报告：模型可能听不出讽刺这类细微的语气。成功和失败的例子都展示。

## 6. 风险和注意事项

| 风险 | 对策 |
|---|---|
| 模型听不出细微的语气（讽刺、撒娇） | 在“语气对”上如实展示；语气不确定时，语气要求退回为“自然的语气” |
| 为了表现语气而乱加内容 | 提示词里明确禁止；检查译文和不带语气要求的版本相比，是否多出了新信息 |
| 合成的日语或中文发音不自然 | 换参考音；换成固定的参考音色；必要时日语改用 GPT-SoVITS 或 VOICEVOX |
| 实时模式延迟增加 | 语音放在字幕之后，作为第三阶段；积压就跳过 |
| **音色克隆的伦理问题** | 只克隆出镜者本人、并且得到本人同意的声音；**不克隆 WMT 视频里的演员或公众人物**；合成语音在页面和视频里标明“AI 合成” |
| CosyVoice 安装麻烦 | 先只做文字层；语音层作为加分项。RTX 50 系上更麻烦，语音层放到 48 GB 的 Ada 或 Ampere 卡上做 |
